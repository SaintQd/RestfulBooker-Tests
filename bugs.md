<a name="auth-1-bug"></a>
## AUTH-1-BUG — Авторизация с верными данными не проходит

**Эндпоинт:** `POST /auth`\
**Связанные тест-кейсы:** `AUTH-1`

### Описание
При попытке осуществления авторизации с имеющимися заранее именем пользователя `admin` и пароле `password123`, авторизация не проходит - в полученном ответе `200 OK` отсутствует токен, вместо него получен ответ `reason: Bad credentials`.

### Предусловия
1. Тестовый стенд доступен.
2. Наличие аккаунта с именем пользователя `admin` и паролем `password123`.

### Шаги воспроизведения
1. Отправить `POST /auth` с верными данными авторизации.

### Ожидаемый результат
Получен ответ `200 OK`, содержащий значение `token`.

### Фактический результат
Получен ответ `200 OK`, содержащий значение `reason: Bad credentials`.

<a name="booking-6-bug"></a>
## BOOKING-6-BUG — Ответ `500 Internal Server Error` при невалидном формате даты в query-параметре

**Эндпоинт:** `GET /booking`\
**Связанные тест-кейсы:** `BOOKING-6`

### Описание
При попытке фильтрации данных бронирования по невалидному параметру `checkin` или `checkout` серверу не удаётся обработать исключение, что приводит к получению ответа `500 Internal Server Error`.

### Предусловия
Тестовый стенд доступен.

### Шаги воспроизведения
1. Обратиться с GET-запросом к эндпоинту `/booking?checkin=2026-13-12`.
2. Повторить с GET-запросом к эндпоинту `/booking?checkout=13993-26-72`.

### Ожидаемый результат
Получен ответ `200 OK`, содержащий пустой список.

### Фактический результат
Получен ответ `500 Internal Server Error`.

<a name="booking-13-bug"></a>
## BOOKING-13-BUG — Ответ `500 Internal Server Error` при создании данных бронирования с неполными данными

**Эндпоинт:** `POST /booking`\

### Шаги воспроизведения
1. Обратиться с POST-запросом к эндпоинту `/booking`. В теле запроса указать все требуемые параметры кроме `firstname` (`lastname`, `totalprice`, `depositpaid`, `checkin`, `checkout`).

### Ожидаемый результат
Получен ответ "400 Bad request".

### Фактический результат
Получен ответ "500 Internal Server Error".

<a name="booking-14-bug"></a>
## BOOKING-14-BUG — Ответ `200 OK` при создании данных бронирования с логически неверными параметрами `checkin` и `checkout`

**Эндпоинты:** `POST /booking`, `PUT /booking{id}`, `PATCH /booking{id}`\
**Связанные тест-кейсы:** `BOOKING-14`, `BOOKING-22`, `BOOKING-14`, `BOOKING-28`

### Описание
При создании или обновлении данных бронирования, в которых дата начала бронирования (`checkin`) начинается позже, чем дата конца бронирования (`checkout`), успешно создаётся новый объект данных или успешно совершается обновление данных, что является логической ошибкой.

### Предусловия
Тестовый стенд доступен, идентификатор 3 существует в базе данных бронирования (для проверки PUT-запроса).

### Шаги воспроизведения
1. Обратиться с POST-запросом к эндпоинту `/booking.` В теле запроса указать все требуемые параметры. Указать в параметре `checkin` значение `2026-09-28`, в параметре `checkout` указать значение `2026-07-23`.
2. Обратиться с PUT-запросом к эндпоинту `/booking/3`. В теле запроса указать в формате объекта JSON все требуемые параметры. В заголовках запроса добавить заголовок `Authorization: Basic YWRtaW46cGFzc3dvcmQxMjM=`. Указать в параметре `checkin` значение `2026-09-28`, в параметре `checkout` указать значение `2026-07-23`.
3. Обратиться с PATCH-запросом к эндпоинту `/booking/3`. В теле запроса указать в формате объекта JSON параметры `checkin=2026-09-28`, `checkout=2026-07-23`. В заголовках запроса добавить заголовок `Authorization: Basic YWRtaW46cGFzc3dvcmQxMjM=`.

### Ожидаемый результат
Получен ответ "400 Bad request", поскольку дата начала бронирования не может быть позже даты конца бронирования.

### Фактический результат
Получен ответ "200 OK", содержащий новый объект с данными бронирования.

<a name="booking-20-bug"></a>
## BOOKING-20-BUG — Неверный код ответа `405 Method Not Allowed` при обновлении или удалении данных бронирования несуществующего идентификатора

**Эндпоинты:** `PUT /booking{id}`, `PATCH /booking{id}`, `DELETE /booking{id}`\
**Связанные тест-кейсы:** `BOOKING-20`, `BOOKING-26`, `BOOKING-31`

### Описание
При попытке обновления или удалении данных бронирования, связанных с несуществующим идентификатором, поступает ответ `405 Method Not Allowed`. Этот код означает, что HTTP-метод не поддерживается ресурсом, тогда как метод поддерживается, а отсутствует сам ресурс. Корректный ответ - `400 Bad Request`.

### Предусловия
Тестовый стенд доступен, идентификатор `100540504` не существует в базе данных бронирования, идентификатор 1 существует в базе данных бронирования.

### Шаги воспроизведения
1. Обратиться с PUT-запросом к эндпоинту `/booking/100540504`. В теле запроса указать в формате объекта JSON все требуемые параметры. В заголовках запроса добавить заголовок `Authorization: Basic YWRtaW46cGFzc3dvcmQxMjM=`.
2. Обратиться с PATCH-запросом к эндпоинту `/booking/100540504`.  В теле запроса указать в формате объекта JSON параметры `firstname`, `lastname`. В заголовках запроса добавить заголовок `Authorization: Basic YWRtaW46cGFzc3dvcmQxMjM=`.
3. Обратиться с DELETE-запросом к эндпоинту `/booking/1`. В заголовках запроса добавить заголовок `Authorization: Basic YWRtaW46cGFzc3dvcmQxMjM=`.

### Ожидаемый результат
Получен ответ `400 Bad request`.

### Фактический результат
Получен ответ `405 Method Not Allowed`.

<a name="booking-33-bug"></a>
## BOOKING-33-BUG — Фильтр данных бронирования по параметру `checkin` не возвращает созданный объект данных

**Эндпоинт:** `GET /booking`\
**Связанные тест-кейсы:** `BOOKING-32`

### Описание
При фильтрации списка бронирований по параметру `checkin` в ответе отсутствует объект данных, созданный перед запросом с указанным параметром `checkin`

### Предусловия
1. Тестовый стенд доступен.

### Шаги воспроизведения
1. Обратиться с POST-запросом к эндпоинту `/booking`. В теле запроса указать в формате объекта JSON параметры: `firstname=firstname`, `lastname=lastname`, `totalprice=100`, `depositpaid=true`, `checkin=2026-07-23`, `checkout=2026-09-28`.
2. Обратиться с GET-запросом к эндпоинту `/booking?checkin=2026-07-23`.

### Ожидаемый результат
`200 OK`, в массиве ответа должен существовать объект со значением bookingid, полученным при создании нового объекта через POST-запрос.

### Фактический результат
`200 OK`, в массиве ответа искомый объект отсутствует.

###
Дополнительно
Фильтры по `checkout`, `firstname` и `lastname` при этом работают корректно.

<a name="booking-34-1-bug"></a>
## BOOKING-34-1-BUG — Ответ `500 Internal Server Error` при передаче числа в поле `firstname` или `lastname`.

**Эндпоинты:** `POST /booking`, `PATCH /booking{id}`\
**Связанные тест-кейсы:** `BOOKING-33`, `BOOKING-34`

### Описание
Создание или полное обновление данных бронирования с числовым значением в строковом поле `firstname` или `lastname` вызывает необрабатываемое исключение, что приводит к получению ответа `500 Internal Server Error` вместо ошибки валидации `400 Bad Request`.

### Предусловия
1. Тестовый стенд доступен.
2. Идентификатор 3 существует в базе данных бронирования (для проверки PUT-запроса).

### Шаги воспроизведения
1. Обратиться с POST-запросом к эндпоинту `/booking`. В теле запроса указать в формате объекта JSON параметры: `firstname=123`, `lastname=lastname`, `totalprice=100`, `depositpaid=true`, `checkin=2026-07-23`, `checkout=2026-09-28`.
2. Повторить с параметрами: `firstname=firstname`, `lastname=123`, `totalprice=100`, `depositpaid=true`, `checkin=2026-07-23`, `checkout=2026-09-28`.
3. Обратиться с PUT-запросом к эндпоинту `/booking/3`. В теле запроса указать в формате объекта JSON параметры: `firstname=123`, `lastname=lastname`, `totalprice=100`, `depositpaid=true`, `checkin=2026-07-23`, `checkout=2026-09-28`.
4. Повторить с параметрами: `firstname=firstname`, `lastname=123`, `totalprice=100`, `depositpaid=true`, `checkin=2026-07-23`, `checkout=2026-09-28`.

### Ожидаемый результат
На каждый запрос получен ответ "400 Bad request"

### Фактический результат
На каждый запрос получен ответ `500 Internal Server Error`.

###
Дополнительно
В случае частичного обновления данных бронирования через PATCH-запрос с числовым значением в строковом поле `firstname` или `lastname` поступает ответ `200 OK`, что является отдельным багом, описанным в баг-репорте `BOOKING-33-2-BUG`.

<a name="booking-34-2-bug"></a>
## BOOKING-34-2-BUG — Отсутствует валидация тела запроса при создании или обновлении данных бронирования

**Эндпоинты:** `POST /booking`, `PUT /booking/{id}`, `PATCH /booking/{id}`\
**Связанные тест-кейсы:** `BOOKING-33`, `BOOKING-34`, `BOOKING-35`

### Описание
Методы создания и обновления принимают данные с нарушением типов и бизнес-логики, возвращают `200 OK` и сохраняют некорректные значения в брони. Валидация входных данных отсутствует.

### Предусловия
1. Тестовый стенд доступен.

### Шаги воспроизведения
1. Отправить POST-запрос на `/booking` или PUT/PATCH-запрос на `/booking/{bookingid}` с валидной авторизацией.
2. В теле запроса передать одно из значений из таблицы ниже.
3. Проверить код ответа.

### Проверенные варианты

| Поле | Переданное значение | Метод | Ожидаемо | Фактически |
|------|---------------------|-------|----------|------------|
| `firstname` | `""` (пустая строка) | POST, PUT, PATCH | 400 | **200** |
| `lastname` | `""` (пустая строка) | POST, PUT, PATCH | 400 | **200** |
| `totalprice` | `"сто"` (строка) | POST, PUT, PATCH | 400 | **200** |
| `totalprice` | `-200` | POST, PUT, PATCH | 400 | **200** |
| `depositpaid` | `"yes"` (строка) | POST, PUT, PATCH | 400 | **200** |
| `bookingdates` | формат `DD.MM.YYYY` | POST, PUT, PATCH | 400 | **200** |
| `additionalneeds` | `""` (пустая строка) | POST, PUT, PATCH | 400 | **200** |

### Ожидаемый результат
Получен ответ `400 Bad Request`.

### Фактический результат
Получен ответ `200 OK`, некорректное значение сохраняется в данные бронирования.

### Дополнительно
Обязательность полей при этом проверяется: отсутствие `firstname`, `lastname`, `totalprice`, `depositpaid` или `bookingdates` в `PUT` корректно возвращает `400`.
